⏺ Plan Modeについて、公式ドキュメントから情報を取得しました。

  Plan Modeとは

  Plan
  Modeは、コードを変更する前に、読み取り専用の操作でコードベースを分析・計画
  を立てるモードです。実際にファイルを書き換えず、まず調査と計画を行います。

  いつ使うか

  - 複雑な機能の実装前：複数ファイルの変更が必要な場合
  - 大規模なリファクタリング：認証システムの移行など
  - コードベースの理解：変更前に徹底的に調査したい
  - 複数のアプローチを検討：実装方法を比較検討したい

  使い方

  1. セッション中に切り替え

  Shift+Tab  # 権限モードを循環
  # Normal → Auto-Accept → Plan Mode
  画面下部に ⏸ plan mode on と表示されます。

  2. 最初からPlan Modeで開始

  claude --permission-mode plan

  3. デフォルトに設定

  .claude/settings.json に追加：
  {
    "permissions": {
      "defaultMode": "plan"
    }
  }

  通常モードとの違い

  |        | 通常モード   | Plan Mode |
  |--------|---------|-----------|
  | ファイル操作 | 読み書き可能  | 読み取り専用    |
  | 実行     | すぐに変更適用 | 計画のみ提示    |
  | 用途     | 実装・修正   | 調査・計画立案   |

  実践例

  claude --permission-mode plan
  > OAuth2を使用するように認証システムをリファクタリングする必要があります。
    詳細な移行計画を作成してください。

  Plan Modeでは、Claudeが：
  1. 現在の認証実装を調査
  2. 影響範囲を分析
  3. 段階的な移行計画を提案
  4. 必要なファイル変更をリストアップ

  計画に納得したら、通常モードに切り替えて実装できます。

  参照ドキュメント

  - https://code.claude.com/docs/en/common-workflows.md#use-plan-mode-for-sa
  fe-code-analysis
  - https://code.claude.com/docs/en/model-config.md#opusplan-model-setting
  - https://code.claude.com/docs/en/sub-agents.md#plan-subagent
  - https://code.claude.com/docs/en/settings.md

  必要性の検討

  arrived_at（ポスト到着日時）

  不要だと思います。理由：
  - scheduled_at があれば、いつ配達されるべきかは分かる
  - ステータス（arrived）で「配達済み」は判別できる
  - 実際の配達日時を記録する必要性が低い
  - MVPでは使わない情報

  もし記録するなら：
  - 統計・分析（予定日と実際の配達日のズレ）
  - デバッグ目的

  moved_to_desk_at（机移動日時）

  同様に不要だと思います。理由：
  - on_desk ステータスで十分
  - 机に移動した日時を表示する必要がない
  - 自動リセットは User.last_reset_date で管理

  もし記録するなら：
  - 「机に何日残っているか」を表示
  - 統計（机に置いておく平均時間）

  提案

  MVPではどちらも削除してシンプルにしましょう。

  必要なカラムのみ：

  # cards テーブル
  - user_id
  - title
  - content
  - status (integer)
  - scheduled_at (datetime)
  - completed_at (datetime) # 完了日時は記録する価値あり
  - snoozed_count (integer)
  - position (integer)
  - timestamps

  モデルも簡略化：

  def arrive!
    update!(status: :arrived)
  end

  def move_to_desk!
    update!(status: :on_desk)
  end
